FEATURE EXPLANATION: BE-3 - LLM Service - Embedding Functionality
================================================================================

OVERVIEW:
---------
Feature BE-3 implements the core LLM (Large Language Model) service for the RecruiterRadar MVP, 
specifically focusing on text embedding functionality. This service provides the foundation for 
converting candidate profiles and search queries into vector representations that enable semantic 
similarity search through the RAG (Retrieval-Augmented Generation) system.

The LLMService uses OpenAI's Embeddings API to generate high-dimensional vector representations 
of text, which will be stored in ChromaDB and used for candidate matching and retrieval.

PURPOSE & BUSINESS VALUE:
------------------------
- Enables semantic search capabilities for candidate matching
- Converts text data into numerical vectors for similarity comparisons
- Provides the foundation for the RAG system that powers intelligent candidate search
- Allows users to find candidates based on meaning and context, not just keyword matching
- Critical component for generating contextual outreach messages in future features

TECHNICAL IMPLEMENTATION:
------------------------

1. SERVICE ARCHITECTURE:
   - Async service class design for non-blocking operations
   - Uses OpenAI's AsyncOpenAI client for API calls

KEY TECHNICAL DECISIONS:
-----------------------

1. API CHOICE:
   - Uses OpenAI's Embeddings API (client.embeddings.create()) - NOT Chat Completions or Responses API
   - Embeddings API is the correct and dedicated endpoint for text vectorization
   - Future text generation will use Chat Completions API (BE-4)

2. MODEL SELECTION:
   - text-embedding-3-small: Balance of performance and cost-effectiveness
   - 1536-dimensional vectors suitable for most similarity search applications
   - Configurable model name for future flexibility

3. ASYNC ARCHITECTURE:
   - Full async/await implementation for FastAPI compatibility
   - Non-blocking API calls prevent server performance issues
   - Compatible with FastAPI's event loop and concurrency model

4. ERROR HANDLING STRATEGY:
   - Progressive backoff for transient errors (rate limits, timeouts)
   - Immediate failure for permanent errors (authentication, bad requests)
   - Clear error messages with appropriate HTTP status codes for API layer
   - Comprehensive logging for debugging and monitoring
